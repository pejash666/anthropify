# anthropify v0.2.0 — AWS Bedrock as the third Anthropic-protocol backend

Status: Approved for v0.2.0 Track D. Companion to
`docs/design/v0.2.0-protocol-driven-adapters.md` (Tracks A/B) and
`docs/design/v0.2.0-cache-control.md` (Track C).
Baseline: v0.2.0 main at `382dbf0`.
Author: anthropify maintainers.

## 1. Goals & Non-goals

### Goals
- Add **AWS Bedrock** as a third backend on the Anthropic-protocol
  family, alongside Anthropic Direct (api.anthropic.com) and MiniMax
  (api.minimax.io/anthropic), keeping the canonical caller surface
  unchanged: callers see `anthropic.MessageNewParams` and
  `anthropic.MessageStreamEventUnion`.
- Delegate every Bedrock-specific concern (SigV4 signing, URL path
  rewrite, `anthropic_version` body injection, `anthropic-beta`
  header→body translation, AWS event-stream decoding) to
  `anthropic-sdk-go`'s official `bedrock` subpackage.
- Public API: a single `WithAnthropicBedrock(name, BedrockConfig)`
  option that registers a Bedrock backend under a user-chosen name,
  routable through the existing `WithModelRoute` / `Route.UpstreamModel`
  machinery exactly like MiniMax.
- Zero breaking changes for v0.1.x and v0.2.0 callers. Existing
  `WithAnthropic` / `WithAnthropicCompat` surface and the raw-HTTP
  code path that powers them stay untouched.

### Non-goals (deferred)
- Multi-account routing / session-hash load balancing (the llm-proxy
  reference implementation has this; users who need it can register
  multiple Bedrock backends under different names and route at the
  application layer).
- A built-in `claude-*` → `anthropic.claude-*-v1:0` mapping table.
  Inference-profile ARNs are account- and region-specific, and the
  AWS-flavored model IDs change per release. The existing
  `Route.UpstreamModel` rewrite hook covers this with zero new API.
- Bearer-token / `AWS_BEARER_TOKEN_BEDROCK` flow. The SDK supports it
  natively; we leave it on the SDK side and only expose the more
  common static-credentials path. Users with bearer tokens can fall
  back to setting the env var, which the SDK's `WithConfig` honours.
- e2e tests against real AWS. AWS keys are non-trivial to revoke and
  the cost / blast-radius of a leaked recording is much higher than
  for the Direct/MiniMax e2e. Unit tests against an `httptest.Server`
  cover every claim we make in this document.

## 2. Why an SDK-delegated Bedrock branch (not raw HTTP)

The existing `adapter/anthropic` adapter constructs raw `*http.Request`
objects and calls `http.Client.Do` directly. This is intentional: the
Anthropic Direct / MiniMax wire protocol is byte-identical to the
canonical `MessageNewParams` JSON shape and the SDK adds nothing.

Bedrock is different. Behind the same wire shape, AWS adds:

1. **SigV4 request signing** (~200 lines, requires keyed HMAC over a
   canonical request).
2. **URL rewrite**: `/v1/messages` → `/model/{id-or-arn}/invoke` or
   `/model/{id-or-arn}/invoke-with-response-stream`, with `model` and
   `stream` stripped from the body and added to the URL.
3. **`anthropic_version` body injection** (default
   `bedrock-2023-05-31`) — Bedrock rejects requests without it.
4. **Beta-header translation**: Bedrock does not accept
   `anthropic-beta` as an HTTP header; the SDK lifts it into the body
   as `anthropic_beta: [...]`.
5. **AWS event-stream decoding**: streaming responses come back as
   `application/vnd.amazon.eventstream` binary frames (not SSE); the
   SDK has a registered decoder that flattens them back into the
   familiar `MessageStreamEventUnion` shape.

Re-implementing items 1–5 inside anthropify is ~300 lines of code that
duplicates work the official SDK already does. Per the codeck-backend
llm-proxy precedent (74 lines, all SDK delegation), the right answer
is to construct an `anthropic.Client` wired through `bedrock.WithConfig`
and dispatch through it for the Bedrock branch only.

The cost of a second code path inside one adapter is small and
contained: a single `if cfg.Mode == AnthropicModeBedrock` switch at the
top of `Adapter.Invoke` and `Adapter.Stream`.

## 3. Public API

### `BedrockConfig`

```go
package anthropify

type BedrockConfig struct {
    // AWS credentials. SessionToken is optional and only used for
    // STS-vended / SSO temporary credentials.
    AccessKeyID     string
    SecretAccessKey string
    SessionToken    string

    // Region is the AWS region of the Bedrock runtime endpoint,
    // e.g. "us-east-1". Required.
    Region string

    // BaseURL overrides the default
    // https://bedrock-runtime.<region>.amazonaws.com host. Intended
    // for tests pointing at httptest.NewServer; production callers
    // should leave it empty.
    BaseURL string

    // ExtraHeaders is merged onto every request before the SDK's
    // bedrock middleware runs. Set "anthropic-beta": "..." here to
    // get the SDK's automatic header→body translation.
    ExtraHeaders http.Header
}
```

### `AnthropicMode` (re-exported from the adapter)

```go
package anthropify

type AnthropicMode = anthropicadapter.AnthropicMode

const (
    AnthropicModeDirect  = anthropicadapter.AnthropicModeDirect  // zero
    AnthropicModeBedrock = anthropicadapter.AnthropicModeBedrock
)
```

`AnthropicMode` is exposed as a re-exported type for symmetry with
`GeminiMode`. It is **not** wired into the public `AnthropicConfig`
struct; users reach Bedrock through `WithAnthropicBedrock`, never by
toggling a `Mode` field. Inside the adapter, `Config.Mode` is a private
discriminator the option machinery sets.

### `WithAnthropicBedrock`

```go
func WithAnthropicBedrock(name string, cfg BedrockConfig) Option
```

Registers a Bedrock backend under the given name. Multiple calls
accumulate; the name is used as the `Route.Backend` value, exactly
like `WithAnthropicCompat`. Internally, this option writes into the
same `c.anthropicCompat[name]` map that `WithAnthropic` /
`WithAnthropicCompat` use, with a private `mode = AnthropicModeBedrock`
flag and a private `bedrock` sub-struct attached.

### Usage

```go
client, err := ap.New(
    ap.WithAnthropic(ap.AnthropicConfig{
        APIKey: os.Getenv("ANTHROPIC_API_KEY"),
    }),
    ap.WithAnthropicBedrock("bedrock", ap.BedrockConfig{
        AccessKeyID:     os.Getenv("AWS_ACCESS_KEY_ID"),
        SecretAccessKey: os.Getenv("AWS_SECRET_ACCESS_KEY"),
        Region:          "us-east-1",
    }),
    ap.WithModelRoute("claude-opus-4-5", ap.Route{
        Provider:      ap.ProviderAnthropic,
        Backend:       "bedrock",
        UpstreamModel: "anthropic.claude-opus-4-5-20250929-v1:0",
    }),
)

req := anthropic.MessageNewParams{
    Model:     "claude-opus-4-5",        // canonical name
    MaxTokens: 1024,
    Messages:  []anthropic.MessageParam{ /* ... */ },
}
msg, err := client.CreateMessage(ctx, req)  // routed to Bedrock
```

Inference-profile ARNs work the same way:

```go
ap.WithModelRoute("claude-opus-4-5", ap.Route{
    Provider:      ap.ProviderAnthropic,
    Backend:       "bedrock",
    UpstreamModel: "arn:aws:bedrock:us-east-1:123456789012:" +
                   "application-inference-profile/abcdef1234",
})
```

## 4. Internal flow

```mermaid
flowchart TB
    User[User code] -->|"req.Model = 'claude-opus-4-5'"| Client["anthropify.Client"]
    Client -->|"Route{Backend:'bedrock', UpstreamModel:'anthropic.claude-opus-4-5-20250929-v1:0'}"| Adapter["adapter/anthropic.Adapter"]
    Adapter --> Branch{"cfg.Mode"}
    Branch -->|Direct (zero)| RawHTTP["raw http.Client.Do<br/>POST /v1/messages"]
    Branch -->|Bedrock| SDKClient["anthropic.NewClient(<br/>bedrock.WithConfig(awsCfg))"]
    SDKClient -->|"SigV4 + URL rewrite +<br/>anthropic_version inject +<br/>beta header→body"| AWS["bedrock-runtime.&lt;region&gt;.amazonaws.com"]
    RawHTTP --> ApiAnthropic["api.anthropic.com /<br/>api.minimax.io/anthropic"]
    SDKClient -->|"MessageStreamEventUnion → RawJSON()"| Translator["adapter.RawEvent stream"]
    Translator --> Client
```

### `New(name, Config)` (adapter level)

1. If `cfg.Mode == AnthropicModeBedrock`:
   - validate AK + SK + Region (SessionToken optional)
   - build `aws.Config{Region, Credentials: credentials.NewStaticCredentialsProvider(AK, SK, SessionToken)}`
   - construct request options: `bedrock.WithConfig(awsCfg)` first,
     then `option.WithBaseURL(cfg.BaseURL)` if non-empty,
     then `option.WithHTTPClient(cfg.HTTPClient)` if non-nil,
     then `option.WithHeaderAdd(k, v)` for each `cfg.ExtraHeaders` entry
   - construct `anthropic.NewClient(opts...)` and stash on
     `Adapter.bedrockClient`. Direct/MiniMax fields are left unset.
2. Otherwise: existing path (validate APIKey, default BaseURL/Version,
   default HTTPClient).

### `Adapter.Invoke(ctx, req)`

- Bedrock branch: `msg, err := a.bedrockClient.Messages.New(ctx, req)`.
  The SDK returns `*anthropic.Message` directly; no JSON round-trip.
- Direct branch: unchanged.

### `Adapter.Stream(ctx, req)`

- Bedrock branch: `stream := a.bedrockClient.Messages.NewStreaming(ctx, req)`.
  In a goroutine, iterate `stream.Next()`, take
  `event := stream.Current()`, push `adapter.RawEvent{Data: []byte(event.RawJSON())}`
  onto the channel. On `stream.Err()` or context cancellation, push a
  terminal `RawEvent{Err: ...}` and close the channel.
  `MessageStreamEventUnion.RawJSON()` returns the original
  per-event JSON the SDK decoded out of the AWS event-stream frame,
  so the bytes pushed into the channel are byte-identical to what the
  Direct branch would emit if Anthropic were the upstream.
- Direct branch: unchanged.

The downstream pipeline (`StreamReader`, `assembleFromStream`) is
content-agnostic — it only cares that bytes parse as Anthropic SSE
event JSON — so no changes are needed past the adapter boundary.

## 5. What the SDK already does for us (verified)

Verified against `anthropic-sdk-go@v1.36.0/bedrock/bedrock.go`:

| Concern | SDK behaviour | File:lines |
|---|---|---|
| SigV4 signing | `v4.NewSigner().SignHTTP(...)` per request | `bedrock.go:206, 285` |
| Bearer auth fallback | `AWS_BEARER_TOKEN_BEDROCK` env var, then `cfg.BearerAuthTokenProvider` | `bedrock.go:198-203, 271-276` |
| URL rewrite | `/v1/messages` → `/model/{model}/invoke[-with-response-stream]` | `bedrock.go:243-259` |
| Strip `model` / `stream` from body | `sjson.DeleteBytes(body, "model"/"stream")` | `bedrock.go:247-248` |
| Inject `anthropic_version` | If body lacks it, set to `bedrock-2023-05-31` | `bedrock.go:230-232` |
| `anthropic-beta` header → body | Strip header, set `anthropic_beta: []string` body field | `bedrock.go:235-241` |
| Set base URL | `https://bedrock-runtime.<region>.amazonaws.com` | `bedrock.go:214` |
| Decode event-stream | Registers `application/vnd.amazon.eventstream` decoder that flattens AWS frames into `ssestream.Event` | `bedrock.go:171-175, 47-160` |

This means anthropify ships **zero** signing, URL-rewrite, or beta-header
translation code. We do not need a port of the llm-proxy
`betaMiddleware`: that file was written against an older SDK release;
v1.36.0 (already pinned in `go.mod`) handles it natively.

## 6. `cache_control` on Bedrock

v0.2.0 Track C added a top-level `cache_control` canonical helper
(`anthropify.SetCacheControl`). It writes the field into
`MessageNewParams` ExtraFields, which serialises to a top-level
`cache_control` key on the wire. Behaviour on Bedrock:

- **Per-block `cache_control`** (the older 4-tag mode): supported by
  Bedrock, transparently forwarded by the SDK. No anthropify changes.
- **Top-level `cache_control`** (v0.2.0 mode): forwarded as-is. AWS
  Bedrock documentation does not currently advertise top-level
  `cache_control` support; we forward verbatim and let the upstream
  silently ignore unsupported fields. README "Prompt caching" section
  carries a one-line caveat.

We deliberately do **not** strip the field on the Bedrock branch.
Stripping would require dialect-aware logic at the adapter level,
which is the wrong place: the canonical contract is "we forward what
you write; the upstream decides". Should Bedrock add support later,
the field flows through with no code change.

## 7. Failure modes and edge cases

- **Missing credentials**: `New(...)` returns
  `errors.New("anthropify/anthropic: AccessKeyID is required for Bedrock mode")`
  (and analogues for SK / Region) before constructing any client.
- **Invalid region**: passed straight through; failures surface as
  `*url.Error` / `*net.OpError` from the SDK on the first request,
  with the standard SDK error wrapping.
- **Authentication failure**: surfaces as the SDK's standard
  `*anthropic.Error` on `Invoke`, or as a `RawEvent{Err: ...}` on
  `Stream`. No special handling needed.
- **Context cancellation during streaming**: `stream.Next()` returns
  false, `stream.Err()` returns `ctx.Err()`. The goroutine drains and
  closes the channel; same shape as the Direct branch.
- **`req.Model` empty**: SDK rejects it during URL rewrite. We do not
  re-validate.

## 8. What this design rejects

- **A built-in model-ID mapping table.** The set of Bedrock model IDs
  (and which ones each AWS account is granted) drifts; inference-profile
  ARNs are account/region-scoped. `Route.UpstreamModel` already does
  exactly the right job and the user is the only authority on which
  mapping is right for their account.
- **Multi-account fan-out / session-hash routing inside one backend.**
  Users who need it register multiple `WithAnthropicBedrock("aws1", ...)`
  / `WithAnthropicBedrock("aws2", ...)` and decide between them at the
  routing layer (e.g. a custom `WithModelOverride`). Keeping this out
  of the adapter avoids embedding a load-balancer in a protocol shim.
- **Auto-pull credentials from `~/.aws/credentials` /
  `AWS_ACCESS_KEY_ID` env vars.** `BedrockConfig` is explicit only.
  Users wanting environment-loaded credentials can build their own
  `aws.Config` and call `bedrock.WithConfig` themselves; we are not in
  the business of replicating the AWS SDK's resolution chain.
- **A standalone `adapter/anthropic_bedrock` package.** The duplication
  of the SSE→`adapter.RawEvent` plumbing and the `Invoke` /
  `Stream` shape would be ~80 lines for negative architectural value.
  One Mode field on `Config` is the smaller change.
